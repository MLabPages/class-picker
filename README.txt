グループ抽選サイト（参加コード・男女均等・Firebase接続・管理画面修正版）

使い方
1. GitHub Pages用には index.html をリポジトリ直下に置いてください。
2. 左上を5回クリック／タップすると管理画面が開きます。
3. 管理コード初期値は reset2026 です。
4. Firebase設定はHTML内に入力済みです。
5. 教員は任意の4桁の参加コードを設定し，表示されたQRコードまたは共有URLを学生に案内してください。学生はQRコードを読み取るか，共有URLをクリックして参加できます。

グループ表示
- 「列番号版」は A1，A2，B1… の形式です。
- 「数字のみ」は 1，2，3… の通し番号です。列ごとに上から番号を振ります。管理画面の列数・1列あたりのグループ数上限・列別の上限で教室の配置に合わせられます。
- 「1列あたりのグループ数上限」は，各列に並べる組数の上限です。空欄のときは，数字のみなら10，列番号版なら全組が入るように自動で決めます。上限なので，実際に1列に並ぶ組数は組数と折り返し方で決まります（例：45組・5列・上限10で「各列の組数をできるだけそろえる」なら各列9組）。管理画面の欄の下に，今の設定での最大が表示されます。
- 折り返し方は「各列の組数をできるだけそろえる」と「1列の上限まで埋めてから次の列へ」から選べます。列番号版と数字のみの両方で使えます。例：45組・5列・1列の上限10なら，前者は各列9組，後者は10・10・10・10・5組です。
- 余り人数の配分は「余った人を後ろの組に1人ずつ加える」（初期値）と「各組に均等配分」から選べます。前者は基準人数より少ない組を作らず，後者は基準人数より多い組を作りません。例：181人・4人基準なら，前者は45組（4人組44，5人組1），後者は46組（4人組43，3人組3）です。183人なら前者は45組（4人組42，5人組3）です。
- 管理画面では，それぞれの選択欄の下に，入力中の人数・列数での組数と列ごとの組数が表示されます。
- 配置枠が必要な組数に足りない場合は，どちらの方式でも配置上限を優先して組数を減らし，人数を再配分します。

抽選の割り当てと欠席者
- Firebase接続時は，空きのある組のうち今の人数が少ない組から順に割り当てます（同じ人数の組どうしはランダム）。欠席者がいても，空いた枠が一部の組に偏りません。男女均等モードでは，人数が同じなら同じ性別が少ない組を先にします。
- 欠席者が次回に抽選する場合は，管理画面で「日付変更時の自動リセット」をオフにして保存しておきます。前回の組分けが残り，後から抽選した人は人数の少ない組に入ります。
- 前回抽選した人は，同じ端末・同じブラウザで開くと前回の番号が再表示されます。別の端末で抽選し直すと，もう1人分の枠を使ってしまいます。
- 人数・表示方式・列数などの配置設定を変えて保存したり，「全員分をリセット」を押したりすると，組分けはリセットされます。
- 管理画面の「抽選状況を表示」では，組ごとの人数に加えて，全体の抽選済み人数と，まだ抽選していない人数を表示します（男女均等モードでは男女別の人数も）。表示中は5秒ごとに自動で更新されます。
- Firebase設定がある場合は，接続や設定・抽選情報の確認に失敗してもローカル版へ切り替えず，抽選を停止します。通信状況を確認して「再接続する」を押してください。接続失敗中は，保存済みの結果を削除せず，共通情報を確認できるまで番号を表示しません。
- 接続失敗中も参加コードの入力・QR表示・管理画面の表示はできますが，設定保存・リセット・抽選状況の表示は停止します。Firebase設定をすべて空にした場合だけ，従来の端末ごとのローカル版として使えます。

修正内容
- JavaScriptの文字列・正規表現の埋め込み崩れを修正しました。
- 管理画面を開く左上5回タップの判定を改善しました。
- Firebase読み書きに失敗しても管理画面は開けるようにしました。
- Firebase設定入りのまま動くようにしました。
- グループ表示に「数字のみ」を追加し，列ごとに上から通し番号を振れるようにしました。
- 余った人を後ろの組に1人ずつ加える方式と，各組に均等配分する方式を管理画面から選べるようにしました。
- 折り返し方（各列の組数をそろえる／1列の上限まで埋めてから次の列へ）を管理画面から選べるようにしました。
- 抽選で，空きのある組のうち人数が少ない組から優先して割り当てるようにしました。欠席者が後日抽選すると人数の少ない組に入ります。
- 抽選状況に，全体の抽選済み人数とまだ抽選していない人数を表示し，表示中は自動で更新するようにしました。
- Firebase設定がある場合の自動的なローカル版への切り替えを禁止し，接続失敗時は抽選停止と再接続の案内を表示するようにしました。
