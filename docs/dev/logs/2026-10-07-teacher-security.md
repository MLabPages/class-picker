# 2026-10-07 教員管理のサーバー境界

ユーザーの指定は、学生のログインを追加せず、教員用管理コードをクラスごとに分けず、1037と7015を1つのコードで管理すること。

本番Firebase Consoleで、rooms直下が `.read: true` / `.write: true` であり、画面の管理コード照合を通らず書ける規則を確認した。これはクライアント設定やUIチェックだけでは解消できない。

対応として、単一HTMLの画面を維持し、Cloudflare Workerへコード照合・所有者照合・設定変更・リセット・定員内抽選を移した。Firebase規則は全クライアント書き込みを拒否し、公開読み取りを必要な葉に絞る。サーバー専用秘密鍵はコードに含めない。既存ルームの公開claim APIは作らず、運用者による明示的な移行だけを用意した。

管理失敗時にローカル設定・既存結果を先に消さないよう順序を変更した。条件付きのルーム更新により結果保存と人数更新を一体化し、定員の競合とリセットとの競合を拒否・再試行する。ルーム切替中の遅い旧応答が新ルームの結果を上書きしないようにした。

別教員・未確認・署名改変・期限切れ・無効化・経路改変、移行によるデータ保持、番号/果物レイアウトの一致、通信失敗・ローカル版の回帰を自動確認。Firebaseエミュレーターで直接書き込み拒否を確認した。画面でも学生抽選・QR・誤コード拒否は確認したが、ブラウザ接続が応答しなくなったため、残りの画面操作は未確認。

公開は未実施。Cloudflare CLIは既存認証の期限切れで、Firebase専用秘密鍵の準備も必要。秘密鍵をCloudflareへ渡す新しいアクセス付与は確認が必要。本番の規則とmainを部分的に変更すると授業を停止させるため、検証済みブランチとdraft PRで保持し、接続・移行・配信をまとめて行う。

最終確認（2026-10-08）：エミュレーター併用で24テスト全件成功。100同時リクエストから定員80の結果を保存し、人数との一致・定員超過なしを確認した（約2.8秒、ローカル環境のみ）。構文・Worker dry-run・diff check成功。Wranglerのsharp依存を修正版0.35.5へ固定後、開発依存を含むnpm auditも0件。
