# 共通管理の接続失敗時に抽選を止める

日付: 2026-10-05

## 目的と変更

- Firebase 設定がある本番用ページで、接続失敗後に全体の残数を確認せずローカル抽選を続ける経路を止めた。Firebase の設定が部分的な場合も停止する。
- 初期化中は抽選ボタンを無効にし、接続・設定取得・既存番号取得・参加コード切り替え・抽選中の通信に失敗した場合は「抽選を停止しています」と「再接続する」を表示する。
- 接続失敗時は端末内の保存済み番号を削除・表示せずに残す。参加コード切り替え時も、共通情報を確認する前に保存結果を消さない。
- 接続失敗中の設定保存・リセット・抽選状況表示を無効にする。参加コード入力・QR 表示・管理画面の表示は残す。Firebase 設定をすべて空にしたローカル版の動作は維持する。
- README、現在状態、判断記録を更新した。組の定員と Firebase のデータ構造は変更していない。

## 検証環境と手順

- Browser plugin not available のため、既存の同梱 Playwright / Chromium を使用した。新規依存は追加していない。
- 対象フロー: 参加コード付き URL を開く → 共通管理の接続または取得に失敗 → 抽選停止 → 再接続 → 共通の既存番号を復元。
- 作業用 HTTP サーバーは `127.0.0.1` の一時ポートのみ。Firebase のモジュールを偽物に差し替え、共通記録をブラウザ内の検証データで代替した。それ以外の外部リクエストは禁止した。
- `node C:\myproject\_scratch\class-picker-connection-qa-20261005\check.cjs` でブラウザ検証を実行。検証終了時にブラウザとサーバーを閉じた。
- デスクトップ 1280×960、モバイル相当 390×844 を確認した。
