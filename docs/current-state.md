# Current state

最終更新: 2026-10-08（教員管理のサーバー境界へ本番切替済み）

## 現在の状態

- 単一ファイル `index.html` に UI、抽選ロジック、QR 生成、Firebase 接続、管理画面がまとまっている。
- 教員は参加コードを作成して共有 URL / QR を配布し、学生は同じコードで参加できる。
- 男女均等、グループ数・行数の上限、配置図、残数管理、管理画面リセットの機能がある。
- 表示方式は A1 形式、数字のみの通し番号、果物から選択できる。数字のみは列ごとに上から番号を振る。
- 1列あたりのグループ数上限は、空欄なら数字のみでは10、列番号版では全組が入るよう自動で決まる。上限なので実際の1列の組数は組数と折り返し方で決まり、管理画面の欄の下に今の設定での最大を表示する。
- 折り返し方は「各列の組数をできるだけそろえる」と「1列の上限まで埋めてから次の列へ」から選択でき、列番号版と数字のみの両方に適用される。折り返し方が保存されていない既存設定は、列番号版をそろえる方式、数字のみを上限まで埋める方式として扱う。
- 余り人数の配分は「余った人を後ろの組に1人ずつ加える」（初期値、基準人数より少ない組を作らない）と「各組に均等配分」（基準人数より多い組を作らない）から選択できる。例：181人・4人基準なら45組（4人組44、5人組1）と46組（4人組43、3人組3）、183人なら前者は45組（4人組42、5人組3）。
- 管理画面では、入力中の設定での組数・人数構成・列ごとの組数を各選択欄の下に表示する。
- 配置枠が必要な組数より少ない場合は、選択方式にかかわらず配置上限を優先し、枠数まで組数を減らして人数を再配分する。
- Firebase 接続時の抽選は、空きのある組のうち今の人数が少ない組から割り当てる（同数はランダム。男女均等モードでは同数なら同じ性別が少ない組を優先）。自動リセットをオフにしておけば、前回の組分けを残したまま欠席者が後日抽選し、人数の少ない組に入る。
- 管理画面の抽選状況は、組ごとの人数に加えて全体の抽選済み人数・未抽選人数（男女均等モードでは男女別も）を表示し、表示中は5秒ごとに読み直す。
- Firebase 設定がある場合は参加コード単位の共通管理を必須とし、初期化・設定や抽選情報の取得・抽選中の通信に失敗すると抽選を停止する。設定が一部でも残っている場合はローカル版へ切り替えない。「再接続する」はページを再読み込みする。
- 接続失敗中は保存済みの結果を削除せず、共通情報を確認できるまで番号の表示と新規抽選を停止する。参加コード切り替えの読み込み失敗時も保存済みの結果を残す。再接続後、同じ抽選セッションの共通記録がある場合は既存の番号を復元し、追加の枠を使わない。
- 接続失敗中も参加コード入力、QR 表示、管理画面の表示は使えるが、設定保存・リセット・抽選状況表示は停止する。Firebase 設定をすべて空にした場合だけ従来の端末ごとのローカル動作を維持する。

## 既知の注意点

- GitHub Pages のような HTTPS 配信を想定している。
- 2026-10-08に本番切替済み。教員コードの照合と担当クラスの権限をCloudflare Workerで確認し、学生のログインを追加せず、教員1人のコードを担当クラス共通で使用する。確認は8時間有効。
- 新Firebase規則はクライアントの書き込みを全て拒否する。共有抽選と管理操作はサーバーで処理し、秘密鍵を画面・Gitへ配信しない。
- 1037 / 7015の移行は抽選記録とsessionIdを保持する。Worker: https://class-picker-api.mlab-tools.workers.dev 。1037 / 7015以外の旧ルーム13件は未移行で抽選不可。詳細は `docs/security-setup.md`。
- Firebase 未設定時は端末間で残数が同期されない。
- 参加コード・表示名・属性などの保存範囲を変更すると、個人情報の扱いも変わる。
