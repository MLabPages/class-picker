# Current state

最終更新: 2026-09-29

## 現在の状態

- 単一ファイル `index.html` に UI、抽選ロジック、QR 生成、Firebase 接続、管理画面がまとまっている。
- 教員は参加コードを作成して共有 URL / QR を配布し、学生は同じコードで参加できる。
- 男女均等、グループ数・行数の上限、配置図、残数管理、管理画面リセットの機能がある。
- 表示方式は A1 形式、数字のみの通し番号、果物から選択できる。数字のみは列ごとに上から番号を振り、初期設定では1列10グループで次の列へ折り返す。
- 余り人数の配分は管理画面で選択できる。初期値は1人余りを最後のグループにまとめ（181人・4人基準なら4人組44、5人組1）、従来方式では必要組数を維持して均等配分（同条件なら46組、4人組43、3人組3）する。
- 配置枠が必要な組数より少ない場合は、選択方式にかかわらず配置上限を優先し、枠数まで組数を減らして人数を再配分する。
- Firebase が使える場合は参加コード単位で状態を共有し、使えない場合は端末ごとの動作に切り替わる。

## 既知の注意点

- GitHub Pages のような HTTPS 配信を想定している。
- Firebase 設定と管理コードがクライアント HTML に含まれるため、公開前にデータベースルールと管理コードを別の安全境界として確認する。
- Firebase 未設定時は端末間で残数が同期されない。
- 参加コード・表示名・属性などの保存範囲を変更すると、個人情報の扱いも変わる。

## 次に確認すること

- 参加コードを URL から開く場合と手入力する場合の両方を確認する。
- QR 表示・共有 URL・学生参加・抽選結果・管理画面リセットを確認する。
- Firebase の読み書きに失敗した場合に、管理画面とローカル動作が適切に継続するか確認する。
