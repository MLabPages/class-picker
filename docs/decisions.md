# Decisions

## 2026-08-20: ルート入口と引き継ぎ文書を分ける

- ルート `AGENTS.md` は作業時の入口と必須制約に絞る。
- 画面・保存・Firebase の状態は `current-state.md`、判断はこのファイル、個別の変更は `dev/logs/` に記録する。
- 利用者向けの操作説明は `README.txt` を正とし、Codex 向けの記録をそこへ過度に混ぜない。

## 既存機能として維持する判断

- 参加コードを URL、QR、入力欄で扱い、授業やクラスごとの抽選を分離する。
- Firebase があれば共有残数を使い、使えない場合も単一端末では動作するフォールバックを残す。
- クライアント側管理画面は利便性のための入口であり、機密データや本格的な権限管理の境界にはしない。

## 2026-09-29: 数字のみのグループ番号と1人余りの扱い

- 表示方式に数字だけの通し番号を追加し、列ごとに上から番号を付ける。初期の列上限は10グループとし、11番以降を次の列に置く。列数や列別上限は既存の管理設定に従う。
- 初期の人数配分は、余りが1人の場合にグループ数を1つ減らし、最後のグループだけ基準人数より1人多くする。181人・4人基準なら45グループ（4人組44、5人組1）となる。
- 管理画面で従来の均等配分も選べる。181人・4人基準なら46グループ（4人組43、3人組3）となる。
- 配置枠が選択方式の必要組数に足りない場合は配置上限を優先し、枠数までグループ数を減らして人数を再配分する。必要に応じて基準人数を超えるグループが生じる。

## 2026-09-29: 余り人数の配分と折り返し方を一般化する

- 「1人余りを最後の組へ」を「余った人を後ろの組に1人ずつ加える」に広げる。基準人数の組を作り、余りの人数分だけ後ろの組を1人増やす。組数が余りより少なく1人ずつ配れない少人数では、均等配分と同じ組数にする。
- 「従来方式」という呼び方をやめ、「各組に均等配分」とする。
- 折り返し方を表示方式から切り離し、「各列の組数をできるだけそろえる」と「1列の上限まで埋めてから次の列へ」を別の設定にする。列番号版で上限まで埋める場合は A 列から順に埋める。
- 折り返し方が未保存の既存設定は、これまでの並び（列番号版：そろえる、数字のみ：上限まで埋める）を保つ。
- 選択肢の文言には特定の人数を入れず、入力中の人数での結果を管理画面に表示する。
- 配置枠が足りない場合の再配分（基準人数を超える組を前から割り当てる）は変えない。
